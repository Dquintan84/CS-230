# CS-230
CS-230 PORTFOLIO
The client for this project was The Gaming Room. They wanted to expand their game, *Draw It or Lose It*, from Android to a web-based application that could run on different operating systems. 
The software needed to support multiple players and teams at the same time while keeping game data organized and secure. The application also needed to be reliable, easy to maintain, and able to grow as more users joined. 
The goal was to design software that would work well now and continue to meet the client's needs in the future.

One thing I think I did well was creating a clear software design document. Breaking the project into sections helped me understand each part of the system before writing any code. 
Comparing different operating systems and explaining why Linux was the best choice also helped strengthen my recommendation. The design document made it easier to organize my ideas and gave me a plan to follow during the coding assignments. 
Instead of trying to solve problems as I coded, I already had a good understanding of how the application should work.

If I could go back and improve one part of my work, I would spend more time on the security section. At the beginning of the course I understood the basics, but later assignments taught me more about authentication, user roles, and protecting data. 
I would update the design to include those ideas in more detail. Working through the design document before coding also showed me how valuable planning can be. 
Creating the UML diagram and thinking about the classes ahead of time made the coding assignments much easier because I already knew how the different parts of the program fit together.

When designing the software, I focused on what the client and future users would need. I chose Linux because it is secure, reliable, and works well for web applications.
I also recommended cloud hosting so the application could grow as more people used it. Throughout the project, I learned that good software design starts with understanding the requirements before writing code. 
In future projects, I will continue to break large problems into smaller pieces, create diagrams before coding, and think about security, performance, and scalability early in the design process. 
This course showed me that careful planning makes development easier and helps create better software.
